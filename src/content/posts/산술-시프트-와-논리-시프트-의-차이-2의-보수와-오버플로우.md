두 방식의 차이는 **2의 보수 방식**과 **부호 비트**를 이해하면 자연스럽게 알 수 있다.

> 자바의 정수는 "2의 보수 체계"를 사용한다.

자바에서 int, long 같은 정수형 타입은 내부적으로 2의 보수 방식으로 음수를 표현한다.

이는 컴퓨터가 음수를 표현하고 계산하기 위한 표준 이진수 체계다.

---

## 왜 2의 보수 방식을 쓰는가?

- 음수 표현 방식 중 하나인 <strong>부호-절대값 방식(기호 비트 따로 두기)</strong>은 연산 회로가 복잡하다는 단점이 존재한다.
- 반면, 2의 보수는 덧셈과 뺄셈을 동일한 방식으로 처리할 수 있어 연산이 단순하고, 하드웨어 구현도 쉽다는 장점이 존재한다.

---

## 2의 보수 만드는 방법

```html
2의 보수 = 1의 보수(비트 반전) + 1
```

예제: -5를 8비트 2의 보수로 표현

- 5의 이진수: 00000101
- 1의 보수 (비트 반전): 11111010
- 2의 보수 = 11111010 + 1 = 11111011
- 따라서 -5는 11111011로 메모리에 저장됨

---

## 양수로 되돌리려면?

- 2의 보수 만드는 방법과 똑같다.
- 11111011 → 00000100 (다시 1의 보수) → 00000101 (+1) → 결과: 5

---

## 부호 판별은 어떻게?

- 최상위 비트(MSB)가 1이면 음수, 0이면 양수

```html
-5 = '1'1111011
+5 = '0'0000101
```

> 즉, 최상위 비트 = 부호 비트 (Signed Integer)

> **그래서 >>와 >>>의 차이는?**

>>와 >>>는 둘 다 오른쪽으로 비트를 민다는 점은 같지만, 밀고난 왼쪽 빈칸에 무엇을 채우느냐가 다르다!

---

## >>와 >>>의 차이

|  |  |  |
| --- | --- | --- |
| **연산자** | **이름** | **역할** |
| >> | 산술(부호 있는) 우측 시프트 | 왼쪽 빈칸을 부호 비트로 채움 |
| >>> | 논리(부호 없는) 우측 시프트 | 왼쪽 빈칸을 항상 0으로 채움 |

---

## 예시

```java
int x = -4;

System.out.println(x >> 1);   // -2
System.out.println(x >>> 1);  // 2147483646
```

|  |  |  |  |
| --- | --- | --- | --- |
| **연산** | **2진수 결과** | **10진수 결과** | **설명** |
| -4 >> 1 | **1**1111111 11111111 11111111 11111110 | -2 | 왼쪽 빈칸을 음수를 뜻하는 1로 채움 |
| -4 >>> 1 | **0**1111111 11111111 11111111 11111110 | 2147483646 | 왼쪽 빈칸을 0으로 채움 |

## 핵심 차이

- >> : 왼쪽을 부호 비트로 채운다 → 따라서 부호가 유지됨
- >>> : 왼쪽을 항상 0으로 채운다 → 즉, 부호 비트까지 밀어버림 → 따라서 결과는 항상 양수

> 왜 이진 탐색에서는 **(left + right) / 2** 보다 **(left + right) >>> 1** 이 안전할까?

다음 예시 코드를 보자.

```java
int left = 2_000_000_000;
int right = 2_000_000_000;

System.out.println((left + right));       // -294967296
System.out.println((left + right) / 2);   // -147483648
System.out.println((left + right) >> 1);  // -147483648
System.out.println((left + right) >>> 1); // 2000000000
```

위 코드에서 (left + right)은 int 범위를 오버플로우하여 음수가 되었다.

> int 범위: -2³¹ ~ 2³¹ - 1= -2,147,483,648 ~ 2,147,483,647 (≈ 2 \* 10^9 ≈ 약 21억)

하지만 우리가 이진 탐색에서 원하는 것은 (left + right)을 정확히 반으로 나눈 값인 mid 값이다.

- / 2: 음수를 나눗셈했으므로 결과는 당연히 음수
- >> 1: 왼쪽 빈칸을 부호 비트로 채우므로, 부호가 유지되어 결과는 여전히 음수
- >>> 1: 왼쪽 빈칸을 무조건 0으로 채우므로, 결과는 양수

따라서 오버플로우 걱정 없이 mid 값을 계산할 때 안전하게 사용할 수 있는 연산자는 <strong>>>></strong>이다.

## int 오버플로우 과정

원래 int는 32비트지만, 간단하게 4비트의 공간이 있다고 가정해 보자.

최상위 비트는 부호 비트이므로, 4비트에서 표현할 수 있는 값은 -2^3 ~ 2^3 - 1 = **-8 ~ 7**

- 4비트에서 최대로 표현할 수 있는 값은 → 0111 = 7 (= 2^3 - 1)
- 여기에 1을 더하면? → 1000 = -8 (부호 비트가 1이 되면서 음수로 인식됨)
- (1000을 양수로 나타내보면 → 0111 + 1 = 1000 = 2^3 = 8이므로, 1000은 -8)

즉, int 범위의 최댓값에 1을 더하면, int 범위의 최솟값이 된다. (맨 위에서 맨 아래로)

## 정리

|  |  |  |
| --- | --- | --- |
| **항목** | **>> (산술 시프트)** | **>>> (논리 시프트)** |
| 부호 유지 여부 | 기존 부호 유지 | 유지하지 않고 무조건 양수로 만듦 |
| 이진 탐색 mid 계산 | ❌ 비추천 (음수 인덱스 위험) | ✅ 추천 (안전하고 정확함) |
| 주요 사용 용도 | 음수와 양수를 모두 고려한 계산 | 비트 연산, 배열 인덱스 계산 |

---

## 마무리

- 자바의 정수는 2의 보수 체계로 동작한다.
- >>와 >>>는 모두 비트 시프트 연산이지만, 왼쪽 빈칸을 어떻게 채우는지가 다르다.
- >>는 부호 비트를 채우고, >>>는 0을 채운다.
- 이진 탐색처럼 인덱스 계산이 필요한 상황에서는 >>보다 >>>를 사용하는 것이 안전하다.
