## 이진 탐색이란?

- **정렬된 수열에서 원하는 값을 빠르게 찾기 위한 탐색 알고리즘**이다.
- 기본적으로 <strong>정렬의 성질(이전 값보다 이후 값이 크다)</strong>을 이용해 <strong>탐색 범위를 절반으로 줄이면서</strong> 탐색한다.

---

## 시간 복잡도는?

- 기본 탐색: O(N)
  - 배열을 처음부터 끝까지 순차 탐색
- **이진 탐색: O(log N)**
  - 배열의 중앙값을 기준으로 절반씩 버리며 탐색

---

## 간단한 예시

[1, 2, 3, 4, 5]에서 5를 찾는다고 가정하자.

- 기본 탐색:
  - 1 → 2 → 3 → 4 → 5 → 찾음
- 이진 탐색:
  - 5는 중간값 3보다 큼 → 탐색 범위를 [4, 5]로 줄임
  - 중간값 4보다 큼 → 탐색 범위를 [5]로 줄임 → 찾음

---

## 핵심 코드

```java
int binarySearch(int[] arr, int target) {
    int left = 0;
    int right = arr.length - 1;

    while (left <= right) {
        int mid = (left + right) >>> 1; // int 오버플로우 방지
        int midVal = arr[mid];

        if (midVal < target) {
            left = mid + 1; // 탐색 범위를 mid 오른쪽으로
        } else if (midVal > target) {
            right = mid - 1; // 탐색 범위를 mid 왼쪽으로
        } else {
            return 1; // target을 찾음
        }
    }

    return 0; // target을 찾지 못함
}
```

> <strong>>>>(논리 시프트 연산자)</strong>를 사용한 이유는 <strong>int형 오버플로우를 방지</strong>하기 위해서다. 자세한 이유는 ? [여기서](/posts/산술-시프트-와-논리-시프트-의-차이-2의-보수와-오버플로우/)

## 예제: 백준 1920번 - 수 찾기

<https://www.acmicpc.net/problem/1920>

N개의 정수 A[1], A[2], …, A[N]이 주어져 있을 때, 이 안에 X라는 정수가 존재하는지 알아내는 프로그램을 작성하시오.

```java
5
4 1 5 2 3
5
1 3 7 9 5
```

첫째 줄에 자연수 N(1 ≤ N ≤ 100,000)이 주어진다. 다음 줄에는 N개의 정수 A[1], A[2], …, A[N]이 주어진다. 다음 줄에는 M(1 ≤ M ≤ 100,000)이 주어진다. 다음 줄에는 M개의 수들이 주어지는데, 이 수들이 A안에 존재하는지 알아내면 된다. 모든 정수의 범위는 -2^31 보다 크거나 같고 2^31보다 작다.

```java
1
1
0
0
1
```

M개의 줄에 답을 출력한다. 존재하면 1을, 존재하지 않으면 0을 출력한다.

---

## 브루트 포스 이용

- **O(M \* N)** = 10^10 → 시간 초과!

---

## 이진 탐색 이용

- 정렬: **O(N log N)**
- 이진 탐색: **O(log N)**
- M개에 대해 이진 탐색: **O(M log N)**
- 전체 시간 복잡도: **O((N + M) log N)** = 2 \* 10^5 \* log 10^5 ≈ 40 \* 10^5 → 가능!

---

## Java 코드

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int N = Integer.parseInt(br.readLine());

        int[] nums = new int[N];

        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            nums[i] = Integer.parseInt(st.nextToken());
        }

        Arrays.sort(nums); // 이진 탐색 위해 정렬

        StringBuilder sb = new StringBuilder();
        int M = Integer.parseInt(br.readLine());

        st = new StringTokenizer(br.readLine());
        for (int i = 0; i < M; i++) {
            int target = Integer.parseInt(st.nextToken());
            sb.append(binarySearch(nums, target)).append('\n');
        }

        System.out.println(sb);
    }

    static int binarySearch(int[] arr, int target) {
        int left = 0;
        int right = arr.length - 1;

        while (left <= right) {
            int mid = (left + right) >>> 1; // int 오버플로우 방지
            int midVal = arr[mid];

            if (midVal < target) {
                left = mid + 1; // 탐색 범위를 mid 오른쪽으로
            } else if (midVal > target) {
                right = mid - 1; // 탐색 범위를 mid 왼쪽으로
            } else {
                return 1; // target을 찾음
            }
        }

        return 0; // target을 찾지 못함
    }
}
```

## 꿀팁: 라이브러리로 간단히 해결하기

```java
int idx = Arrays.binarySearch(arr, target);

if (idx < 0) {
    sb.append(0);
} else {
    sb.append(1);
}
```

- Arrays.binarySearch()는 target이 존재하지 않으면, **-(삽입 위치 + 1)** 값이 반환된다.
- (삽입 위치 = 정렬을 유지하며 target이 들어갈 위치)
- 즉, 음수가 반환되면 값이 존재하지 않는 것이다.

## HashSet을 사용한 O(N + M) 풀이 방법

- HashSet은 내부적으로 **HashMap 기반**으로 구현되어 있음
- 대부분의 연산이 **평균적으로 O(1)** 시간에 수행됨
  - 요소 추가: HashSet.**add**(key)
  - 요소 포함 여부 확인: HashSet.**contains**(key)
- N개의 수를 넣고, M번 존재 여부 조회 → **O(N + M)**
  - 시간 복잡도는 낮지만 메모리 공간을 더 차지하므로, **공간 vs 시간** 트레이드오프 존재

---

## 정리

- 이진 탐색은 <strong>O(log N)</strong>에 탐색 가능하므로, <strong>큰 입력에도 강력하다.</strong>
- **>>> 1**로 mid 계산 시 오버플로우를 방지 할 수 있다.
- 처음엔 순차 탐색을 해보고, 시간 초과가 발생할 것 같다면 이진 탐색을 고려해 보자.
