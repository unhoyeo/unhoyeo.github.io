<https://www.acmicpc.net/problem/17298>

크기가 N인 수열 A = A1, A2, ..., AN이 있다. 수열의 각 원소 Ai에 대해서 오큰수 NGE(i)를 구하려고 한다. Ai의 오큰수는 오른쪽에 있으면서 Ai보다 큰 수 중에서 가장 왼쪽에 있는 수를 의미한다. 그러한 수가 없는 경우에 오큰수는 -1이다.

예를 들어, A = [3, 5, 2, 7]인 경우 NGE(1) = 5, NGE(2) = 7, NGE(3) = 7, NGE(4) = -1이다. A = [9, 5, 4, 8]인 경우에는 NGE(1) = -1, NGE(2) = 8, NGE(3) = 8, NGE(4) = -1이다.

```java
4
3 5 2 7
```

첫째 줄에 수열 A의 크기 N (1 ≤ N ≤ 1,000,000)이 주어진다. 둘째 줄에 수열 A의 원소 A1, A2, ..., AN (1 ≤ Ai ≤ 1,000,000)이 주어진다.

```java
5 7 7 -1
```

총 N개의 수 NGE(1), NGE(2), ..., NGE(N)을 공백으로 구분해 출력한다.

---

## 시간 초과하는 풀이

- 2중 for문으로 순회하면서 자신보다 오른쪽에 있는 수가 자신보다 크다면 결과에 추가
- 만약 해당하는 수가 없는 경우 -1 추가 → boolean flag 이용
- **N ≤ 1,000,000**이므로, 2중 for문은 시간 초과된다.

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int N = Integer.parseInt(br.readLine());

        int[] arr = new int[N];

        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < N; i++) {
            boolean flag = false;
            for (int j = i + 1; j < N; j++) {
                if (arr[j] > arr[i]) {
                    sb.append(arr[j]);
                    flag = true;
                    break;
                }
            }
            if (!flag) sb.append(-1);
            sb.append(' ');
        }

        System.out.println(sb);
    }
}
```

## 올바른 아이디어

- 오큰수(NGE, Next Greater Element) 문제는 **스택**을 이용하여 **한 번의 순회**로 해결할 수 있다.
- **두 가지 순회 방식**이 존재한다. (왼쪽 → 오른쪽 순회, 오른쪽 → 왼쪽 순회)

## 왼쪽 → 오른쪽 순회 (순방향)

- 현재 인덱스를 기준으로 **앞에서 보류해둔 값들**의 오큰수를 처리함
- 스택에는 **아직 오큰수가 정해지지 않은 인덱스들**이 저장됨
- **현재 값이 스택 top 인덱스의 값보다 크면**, 해당 인덱스의 오큰수를 현재 값으로 기록하고 pop함

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int N = Integer.parseInt(br.readLine());

        int[] arr = new int[N];

        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        Stack<Integer> stack = new Stack<>();
        int[] answer = new int[N];

        for (int i = 0; i < N; i++) {
            // 현재 값이 아직 오큰수를 모르는 값보다 큰 경우 (현재 값이 오큰수인 경우)
            while (!stack.isEmpty() && arr[i] > arr[stack.peek()]) {
                answer[stack.pop()] = arr[i];
            }
            // 아니면 현재 인덱스의 오큰수 지정을 보류
            stack.push(i);
        }

        // 마지막까지 보류된 인덱스들은 오큰수가 없음
        while (!stack.isEmpty()) {
            answer[stack.pop()] = -1;
        }

        StringBuilder sb = new StringBuilder();
        for (int n : answer) {
            sb.append(n).append(' ');
        }

        System.out.println(sb.toString().trim());
    }
}
```

## 예시 흐름 (arr = [3, 5, 2, 7])

- 3 → 스택에 넣음
- 5 → 3보다 크므로 3의 오큰수는 5 → 3 pop
- 2 → 작으므로 보류
- 7 → 2보다 큼 → 2의 오큰수는 7, 5보다 큼 → 5의 오큰수는 7

## 오른쪽 → 왼쪽 순회 (역방향)

- 오른쪽 끝부터 왼쪽으로 하나씩 보면서 **현재 값보다 큰 값을 스택에서 찾음**
- 스택에는 **자신보다 오른쪽에 있는 원소들 중 오큰수가 될 수 있는 후보**만 저장됨
- 현재 값을 기준으로 스택에서 **작거나 같은 값들은 모두 pop (제거)**
- 스택에 값이 남아 있다면 **top 값이 오큰수** (없으면 -1)

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int N = Integer.parseInt(br.readLine());

        int[] arr = new int[N];

        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            arr[i] = Integer.parseInt(st.nextToken());
        }

        Stack<Integer> stack = new Stack<>();
        int[] answer = new int[N];

        for (int i = N - 1; i >= 0; i--) {
            // 스택에서 현재 값보다 작거나 같은 값은 모두 제거 (오큰수 찾기)
            while (!stack.isEmpty() && stack.peek() <= arr[i]) {
                stack.pop();
            }

            // 제거 후 맨 위에 있는 값이 바로 오큰수 (없다면 오큰수 없음)
            if (stack.isEmpty()) answer[i] = -1;
            else answer[i] = stack.peek();

            // 현재 값을 스택에 넣음 (오큰수 후보)
            stack.push(arr[i]);
        }

        StringBuilder sb = new StringBuilder();
        for (int n : answer) {
            sb.append(n).append(' ');
        }

        System.out.println(sb.toString().trim());
    }
}
```

## 예시 흐름 (arr = [3, 5, 2, 7])

- 7 → 스택 비어있음 → -1
- 2 → 스택 top(7) > 2 → 7
- 5 → 스택 top(7) > 5 → 7
- 3 → 스택 top(5) > 3 → 5

---

## 시간 복잡도

- 각 원소가 한 번만 스택에 push/pop 되므로 **O(N)**
- N ≤ 1,000,000이라 **반드시 이 알고리즘을 사용해야 한다.** (브루트 포스는 O(N^2) → 시간 초과)

## 비교 요약

|  |  |  |
| --- | --- | --- |
| **항목** | **왼쪽 → 오른쪽 순회** | **오른쪽 → 왼쪽 순회** |
| 순회 방향 | 순방향 (인덱스 0부터) | 역방향 (인덱스 N - 1부터) |
| 스택에 저장되는 값 | **오큰수가 아직 없는 인덱스** | **오큰수가 될 수도 있는 값** |
| 스택에서 pop 조건 | 현재 값이 스택 top 값보다 클 때 | 스택 top 값이 현재 값보다 작거나 같을 때 |
| 사용 예 | 오큰수 외 다른 문제에 응용 가능 | 오큰수 문제에 가장 적합한 방식 |

## 결론

- 두 풀이 모두 실전에서 널리 쓰이며, 문제에 따라 더 적절한 방향을 선택하면 된다.
- **오큰수 문제**에서는 **오른쪽 → 왼쪽** 순회 방식이 효율적이고 구현도 단순하기 때문에 일반적으로 더 많이 사용된다.
- **왼쪽 → 오른쪽** 순회 방식은 문제를 직관적으로 이해하거나 변형 문제(예: **오큰수 인덱스를 저장**하는 경우)에 유리할 수 있다.
