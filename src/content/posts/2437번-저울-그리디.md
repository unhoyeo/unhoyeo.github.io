<https://www.acmicpc.net/problem/2437>

하나의 양팔 저울을 이용하여 물건의 무게를 측정하려고 한다. 이 저울의 양 팔의 끝에는 물건이나 추를 올려놓는 접시가 달려 있고, 양팔의 길이는 같다. 또한, 저울의 한쪽에는 저울추들만 놓을 수 있고, 다른 쪽에는 무게를 측정하려는 물건만 올려놓을 수 있다.

무게가 양의 정수인 N개의 저울추가 주어질 때, 이 추들을 사용하여 측정할 수 없는 양의 정수 무게 중 최솟값을 구하는 프로그램을 작성하시오.

예를 들어, 무게가 각각 3, 1, 6, 2, 7, 30, 1인 7개의 저울추가 주어졌을 때, 이 추들로 측정할 수 없는 양의 정수 무게 중 최솟값은 21이다.

```java
7
3 1 6 2 7 30 1
```

첫 째 줄에는 저울추의 개수를 나타내는 양의 정수 N이 주어진다. N은 1 이상 1,000 이하이다. 둘째 줄에는 저울추의 무게를 나타내는 N개의 양의 정수가 빈칸을 사이에 두고 주어진다. 각 추의 무게는 1이상 1,000,000 이하이다.

```java
21
```

첫째 줄에 주어진 추들로 측정할 수 없는 양의 정수 무게 중 최솟값을 출력한다.

---

**아이디어**

- 추들을 오름차순으로 정렬한 후, 그리디 알고리즘을 이용한다.
- **target = 현재까지 측정 가능한 최대 무게 + 1**이라 정의한다.
  - 즉, <strong>"1부터 target - 1까지는 모두 잴 수 있다"</strong>는 전제 아래 탐색을 진행한다.
- 정렬된 추 배열을 순회하며, 각 추의 무게 w에 대해:
  - **w ≤ target**인 경우:
    - 기존에 만들 수 있는 구간에 이 추를 더해 **target까지 포함하는 새로운 구간**을 만들 수 있으므로, **target += w**
  - **w > target**인 경우:
    - 이 추를 포함해도 그 사이 값인 target을 만들 수 없으므로, 그 순간의 target이 **측정 불가능한 최소 무게**가 된다.

- **왜 이 방식이 맞는가?**
  - target까지 가능한지 여부는 **지금까지 조합으로 만들 수 있는 연속 구간**을 유지하면서 확인하는 것이다.
  - 이 범위를 확장할 수 없게 되는 첫 시점이 바로 **가장 작은 측정 불가능 무게**다.
  - 이후의 추들이 아무리 많고 커도, 그 빈 구간을 채울 수 없으므로 탐색을 종료해야 한다.

---

⏱️ **시간 복잡도**

- 정렬: **O(N log N)**
- 그리디 N번 반복: **O(N)**

→ 전체 시간 복잡도: **O(N log N)**

---

**Java 코드**

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int N = Integer.parseInt(br.readLine());

        int[] weights = new int[N];

        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 0; i < N; i++) {
            weights[i] = Integer.parseInt(st.nextToken());
        }

        Arrays.sort(weights);

        int target = 1; // 만들 수 없는 가장 작은 무게

        for (int w : weights) {
            if (w > target) break;
            target += w;
        }

        System.out.println(target);
    }
}
```

## 예제 시각화

```
정렬된 추: [1, 1, 2, 3, 6, 7, 30]
초기 target = 1
```

- 1 ≤ 1 → target += 1 → target = 2
  - 1 측정 가능? → 추가 1이라 가능 → 측정 가능 구간: [1]
- 1 ≤ 2 → target += 1 → target = 3
  - 2 측정 가능? → 기존에 1까지 가능했고, 이제 1이 추가됐으므로 가능 → 측정 가능 구간: [1, 2]
- 2 ≤ 3 → target += 2 → target = 5
  - 3 측정 가능? → 기존에 2까지 가능했고, 이제 2가 추가됐으므로 조합해서 4까지 가능 → 측정 가능 구간: [1, 4]
- 3 ≤ 5 → target += 3 → target = 8
  - 5 측정 가능? → 기존에 4까지 가능했고, 이제 3이 추가됐으므로 조합해서 7까지 가능 → 측정 가능 구간: [1, 7]
- 6 ≤ 8 → target += 6 → target = 14
  - 8 측정 가능? → 기존에 7까지 가능했고, 이제 6이 추가됐으므로 조합해서 13까지 가능 → 측정 가능 구간: [1, 13]
- 7 ≤ 14 → target += 7 → target = 21
  - 14 측정 가능? → 기존에 13까지 가능했고, 이제 7이 추가됐으므로 조합해서 20까지 가능 → 측정 가능 구간: [1, 20]
- 30 > 21 → 종료, 정답 = 21
  - 21 측정 가능? → 기존에 20까지 가능했는데, 30이 추가됐으므로 21 ~ 29는 젤 수 없음
