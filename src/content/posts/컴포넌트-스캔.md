지금까지는 **AppConfig**(설정 정보 클래스)에 **@Bean**을 통해 직접 **등록할 스프링 빈을 나열**했다.

그런데 등록할 스프링 빈이 많아지면 일일이 등록하기도 귀찮고, 설정 정보도 커지고, 누락하는 문제도 발생한다.

그래서 스프링은 설정 정보가 없어도, **자동으로 스프링 빈을 등록**하는 **"@ComponentScan"** 기능을 제공한다.

또한 **의존관계도 자동으로 주입**하는 **"@Autowired"** 기능도 제공한다.

---

컴포넌트 스캔을 사용하려면 **@ComponentScan** 애노테이션을 **설정 정보 클래스**(AppConfig)에 붙여주면 된다.

```java
@Configuration
@ComponentScan
public class AppConfig {
}
```

컴포넌트 스캔은 말 그대로 **@Component** 애노테이션이 붙은 클래스를 **스캔**해서 **스프링 빈으로 등록**한다.

> **@Configuration** 안에도 @Component가 들어있다. 따라서 @Configuration이 붙은 클래스도 **컴포넌트 스캔 대상**에 포함된다.

따라서, 이제는 각 클래스를 스프링 빈으로 등록하고 싶을 때, 컴포넌트 스캔의 대상이 되도록 **@Component**를 붙여주면 된다.

```java
@Component
public class MemoryMemberRepository implements MemberRepository { ... }
```

```java
@Component
public class MemberServiceImpl implements MemberService {

    private final MemberRepository memberRepository; // 의존관계 주입은?

    @Autowired // 의존관계 자동 주입!
    public MemberServiceImpl(MemberRepository memberRepository) {
        this.memberRepository = memberRepository;
    }

    ...
}
```

MemberServiceImpl은 **MemberRepository**와 의존관계가 있다. 따라서 **"의존관계 주입"**을 해줘야 하는데, 기존에는 AppConfig에 일일이 명시를 해줬지만, **컴포넌트 스캔을 사용하는 AppConfig**에는 그런 것이 하나도 없다.

그래서 의존관계 주입도 **이 클래스 안에서** 해결해야 한다.

이를 위해서는 **"@Autowired"** 애노테이션을 **"생성자"**에 달아주면 된다. 이렇게 하면 스프링이 알아서 **의존관계를 자동 주입**해 준다.

**의존관계 자동 주입**에 대해서는 다음 글에서 자세히 알아보자.

---

## 중간 정리

- **@ComponentScan**은 **@Component**가 붙은 모든 클래스를 스캔해서 **스프링 빈으로 등록**한다.
  - 이때 스프링 빈의 이름은 기본적으로 **클래스 이름**을 사용하되, **맨 앞글자만 소문자**를 사용한다.
- 생성자에 **@Autowired**를 지정하면, **스프링 컨테이너가 해당 빈을 찾아서 자동 주입**한다.
  - 이때 기본 조회 전략은 **"타입이 같은 빈"**
  - 즉, 위의 경우 getBean(MemberRepository.class)와 같이 동작한다.

> **컴포넌트 스캔 - 시작 위치**

모든 클래스를 컴포넌트 스캔하기에는 시간이 오래 걸리기 때문에 **특정 패키지부터 하위 패키지**를 탐색하도록 시작 위치를 지정할 수 있다.

```java
@ComponentScan(basePackages = "com.spring.study")
```

- basePackages = {"xxx", "yyy"} 이렇게 **여러 시작 위치**를 지정할 수도 있다.
- basePackageClasses 옵션으로 **특정 클래스의 패키지**를 시작 위치로 지정할 수도 있다.
- 아무 옵션도 지정하지 않으면 **@ComponentScan이 붙어있는 클래스의 패키지**가 시작 위치가 된다.

> 패키지 위치를 지정하는 것보다는 **설정 정보 클래스의 위치를 프로젝트 최상단**에 두는 것이 권장된다.
> 스프링 부트의 대표 시작 정보인 @SpringBootApplication이 붙여진 클래스도 프로젝트 최상단에 있는데, 이 애노테이션 안에 바로 @ComponentScan이 들어있다.

> **컴포넌트 스캔 - 기본 대상**

컴포넌트 스캔은 **@Component** 뿐만 아니라 다음 애노테이션도 컴포넌트 스캔 대상에 포함한다.

- **@Configuration** : 스프링 설정 정보에서 사용
- **@Controller** : 스프링 MVC 컨트롤러에서 사용
- **@Service** : 스프링 비즈니스 로직에서 사용
- **@Repository** : 스프링 데이터 접근 계층에서 사용

해당 애노테이션의 코드를 보면 @Component가 들어있는 것을 알 수 있다.

> 사실 **애노테이션에는 상속관계라는 개념이 없다**. 그래서 이렇게 어떤 애노테이션이 특정 애노테이션을 가지고 있는 것을 알 수 있는 것은 자바가 지원하는 기능이 아니라, **스프링**이 지원하는 기능이다.

위의 애노테이션들은 컴포넌트 스캔 용도뿐만 아니라 다음과 같은 **부가 기능**도 수행한다.

- **@Configuration** : 스프링 설정 정보로 인식하고, 스프링 빈이 **싱글톤**을 유지하도록 추가 처리를 한다. (이전 글의 CGLIB 참고)
- **@Controller** : 스프링 MVC 컨트롤러로 인식한다.
- **@Service** : 사실 특별한 처리를 하지 않는다. 대신 개발자들이 비즈니스 계층을 인식하는데 도움이 된다.
- **@Repository** : 스프링 데이터 접근 계층으로 인식하고, 데이터 계층의 예외를 스프링 예외로 변환해 준다.

> **컴포넌트 스캔 - 필터**

- **includeFilters** : 컴포넌트 스캔 대상에 추가로 포함할 클래스를 지정한다.
- **excludeFilters** : 컴포넌트 스캔 대상에서 제외할 클래스를 지정한다.

```java
@ComponentScan(
        includeFilters = @ComponentScan.Filter(
                type = FilterType.ANNOTATION,
                classes = 포함할클래스.class
        ),
        excludeFilters = @ComponentScan.Filter(
                type = FilterType.ANNOTATION,
                classes = 제외할클래스.class
        )
)
```

FilterType에는 5가지 옵션이 있다.

- **ANNOTATION** : 기본값, 애노테이션을 인식해서 동작한다. ex) org.example.SomeAnnotation
- **ASSIGNABLE\_TYPE** : 지정한 타입과 자식 타입을 인식해서 동작한다. ex) org.example.SomeClass
- **ASPECTJ** : AspectJ 패턴 사용 ex) org.example..\*Service+
- **REGEX** : 정규 표현식 ex) org\.example\.Default.\*
- **CUSTOM** : TypeFilter이라는 인터페이스를 구현해서 처리 ex) org.example.MyTypeFilter

> **컴포넌트 스캔 - 빈 이름 중복 충돌**

컴포넌트 스캔에서 **빈 이름이 중복**될 경우 어떻게 될까?

## case1 : 자동 빈 등록 vs 자동 빈 등록

컴포넌트 스캔에 의해 자동으로 등록된 빈의 이름이 같은 경우, **ConflictingBeanDefinitionException** 예외를 발생시킨다.

## case2 : 수동 빈 등록 vs 자동 빈 등록

내가 직접 @Bean으로 수동 등록한 빈과 @Component로 자동 등록된 빈의 이름이 중복되는 경우, **수동 등록**된 빈이 **오버라이딩**된다.

하지만 이 경우에는 개발자가 의도적으로 했다기보다는 여러 설정이 꼬여서 발생했을 가능성이 더 높다.

따라서 **스프링부트**에서는 수동 빈 등록과 자동 빈 등록이 충돌 나면 **오류가 발생**하도록 기본값을 바꾸었다.

> Description:
>
> The bean 'memoryMemberRepository', defined in class path resource [com/spring/study/AppConfig.class], could not be registered. A bean with that name has already been defined in file [/........./com/spring/study/MemoryMemberRepository.class] and overriding is disabled.
>
> Action:
>
> Consider renaming one of the beans or enabling overriding by setting spring.main.allow-bean-definition-overriding=true
