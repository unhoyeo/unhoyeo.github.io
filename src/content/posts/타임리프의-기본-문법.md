우선 타임리프를 사용하려면 &lt;html> 태그에 다음과 같이 선언해야 한다.

```html
<html xmlns:th="http://www.thymeleaf.org">
```

---

## 변수 출력 – th:text, th:utext, [[...]], [(...)]

```haxe
model.addAttribute("user", new User("<b>홍길동</b>", 25))
```

```html
<!-- &lt;b&gt;홍길동&lt;/b&gt; 출력 (escaped) -->
<span th:text="${user.name}">이름</span>
<span th:utext="${user.name}">이름</span>

<!-- 굵은 글씨로 홍길동 출력 (unescaped) -->
<span>[[${user.name}]]</span>
<span>[(${user.name})]</span>
```

- **th:text**
  - 타임리프의 표준 속성
  - 해당 HTML 요소의 **텍스트 콘텐츠를 출력**하고, 기존 콘텐츠를 **덮어씀**
  - XSS(Cross Site Scripting) 방지를 위해 **HTML escape 처리가 자동 적용**됨
- **th:utext**
  - "unescaped text"의 약자
  - th:text와 마찬가지로 텍스트를 출력하지만, **HTML escape 없이 그대로 출력**
  - HTML 태그를 포함한 콘텐츠를 브라우저에 직접 렌더링 하고 싶을 때 사용
- **[[...]]**
  - 타임리프의 **텍스트 인라인 표현식**
  - HTML 속성이 아닌 **HTML 콘텐츠 안에서** 사용함
  - th:text와 동일하게 HTML escape 적용됨
- **[(...)]**
  - 타임리프의 **unescaped 인라인 표현식**
  - th:utext와 동일하게 **HTML escape 없이 그대로 출력**

- **${user.name}**
  - Model에 전달된 user 객체의 **name 프로퍼티**에 접근하는 **SpringEL**(Spring Expression Language) 표현식
  - 내부적으로 SpringEL 파서에 의해 값이 평가됨
    - user라는 이름으로 Model에서 객체를 찾은 뒤,
    - 해당 객체의 getName() 메서드를 호출하여 값을 반환함
    - 즉,${user.name} → user.getName()과 동일한 의미

> **HTML 엔티티**: <, >, &, ", ' 등의 특수 문자는 HTML 태그나 속성 구문과 충돌할 수 있기 때문에, 브라우저가 혼동하지 않도록 엔티티 (&로 시작해서 ;로 끝나는 형식)로 표현한다. 이러한 엔티티를 사용하면 브라우저가 해당 문자를 태그가 아닌 문자로 인식하게 된다.

> **Escape**: 특수 문자를 HTML 엔티티로 변환해서 출력 (예: `<b>홍길동</b>` → `&lt;b&gt;홍길동&lt;/b&gt;`)
> **Unescape**: HTML 엔티티를 다시 원래 문자로 복원 (예: `&lt;b&gt;홍길동&lt;/b&gt;` → `<b>홍길동</b>`)

> 사용자 입력 데이터에 &lt;script>...&lt;/script> 등이 포함되어 있으면 브라우저에서 스크립트가 실행될 위험이 있다. (XSS)
> 따라서 외부 사용자 입력을 출력할 때는 기본적으로 escape 처리가 되는 th:text 또는 [[...]] 방식을 사용하는 것이 안전하다.

> SpringEL은 OGNL(Object Graph Navigation Language)에서 영향을 받은 표현식 언어로, 타임리프에서 객체 접근, 조건 분기, 반복 등에 사용하는 표현식 언어이다. 타임리프는 이 표현식을 HTML 태그의 속성(th:text, th:if 등)이나 텍스트 출력 문법([[...]], [(...)])과 함께 사용하여 동적 웹 페이지를 생성한다. (예: ${user.age}, ${userList[0].age}, ${userMap['홍길동'].age})

## 지역 변수 – th:with

```applescript
<div th:with="변수명=값">
    ...
</div>
```

- **해당 태그 안 또는 하위 요소에서만 유효**한 지역 변수(Local Variable)를 선언할 때 사용하는 속성
- 일시적으로 값을 가공하거나, 복잡한 식을 단순화하는 데 사용됨

예시:

```html
<!-- 복잡한 식을 미리 계산해 변수로 저장 -->
<div th:with="fullName=${user.firstName + ' ' + user.lastName}">
    <p th:text="${fullName}">Harry Potter</p>
</div>

<!-- 조건 처리와 함께 사용 -->
<div th:with="isAdult=${user.age >= 20}">
    <span th:if="${isAdult}" th:text="'성인입니다.'"></span>
    <span th:unless="${isAdult}" th:text="'미성년자입니다.'"></span>
</div>

<!-- 루프 내에서 가공된 값 저장 -->
<tr th:each="item : ${items}" th:with="totalPrice=${item.price * item.quantity}">
    <td th:text="${item.name}">상품명</td>
    <td th:text="${totalPrice}">총액</td>
</tr>
```

## URL 링크 – @{...} 표현식

```html
<!-- 정적 URL 링크 -->
<a th:href="@{/hello}">링크</a>

<!-- 경로 변수 -->
<a th:href="@{/users/{id}(id=${user.id})}">회원 상세</a>

<!-- 쿼리 파라미터 -->
<a th:href="@{/search(q=${keyword}, page=${page})}">검색</a>
```

- **@{...}**
  - **동적으로 URL을 생성**할 때 사용하는 표현식
  - **링크(th:href), 이미지(th:src), 폼 액션(th:action)** 등에서 사용됨
  - 내부적으로 **URL 인코딩**도 자동 처리됨
  - Spring MVC의 URL 패턴과 자연스럽게 연동됨

- **경로 변수**
  - {변수명}(변수명=값) 형식으로 바인딩
  - /users/{id}에서 경로 변수는 {id}이며, <strong>(id=${user.id})</strong>를 통해 동적으로 값이 바인딩됨

- **쿼리 파라미터**
  - (...)에서 **경로 변수로 바인딩되지 않은 변수**들이 쿼리 파라미터로 생성됨
  - (key1=${val1}, key2=${val2}) 형식으로 전달

혼합 예시:

```html
<!-- 경로 변수 + 쿼리 파라미터 -->
<a th:href="@{/board/{id}(id=${board.id}, title=${title})}">검색</a>
```

- board.id = 2, title = 'spring'인 경우 → /board/2?title=spring

> @{/path} : 웹 애플리케이션 루트(/)부터 시작하는 절대 경로
> @{path} : 현재 경로 기준의 상대 경로
> (대부분의 경우 절대 경로를 사용하는 것이 안전)

## 리터럴 (Literal)

- 표현식 내에서 그 자체로 사용되는 **고정된 값**
- 문자열, 숫자, 불리언, 날짜, null 등 다양한 타입을 포함함
- 타임리프에서 문자 리터럴은 **항상 '작은따옴표'로 감싸야함** (공백 없이 하나의 토큰인 경우 생략 가능)

```html
<span th:text="'Hello World'">기본값</span>
<span th:text="'Hello ' + ${data}">기본값</span>
<span th:text="123 + 456">기본값</span>
<span th:if="true">조건이 참일 때만 표시</span>
```

---

## 리터럴 대체 (Literal Substitutions)

- 문자열 안에 변수 값을 ${...} 또는 \*{...} 표현식으로 삽입할 수 있게 해주는 타임리프만의 특별한 문법
- **|...| 기호로 감싸고, 내부에 ${...} 또는 \*{...}를 삽입**
- 즉, 문자열 템플릿 안에 변수를 포함시키는 방식
- 기존 방식에 비해 훨씬 간결하고 읽기 쉬우며, 불필요한 따옴표와 연산자를 줄일 수 있음

```html
<!-- 기존 방식 (문자열 연결) -->
<span th:text="'안녕하세요, ' + ${user.name} + '님'">기본</span>

<!-- 리터럴 대체 방식 -->
<span th:text="|안녕하세요, ${user.name}님|">기본</span>
```

## 속성 값 설정 – th:attrappend, th:attrprepend, th:classappend

```
<!-- 속성 값 뒤에 추가 (append) -->
<input class="base" th:attrappend="class=' active'">
렌더링 결과: <input class="base active">

<!-- 속성 값 앞에 추가 (prepend) -->
<input class="base" th:attrprepend="class='highlight '">
렌더링 결과: <input class="highlight base">

<!-- 클래스 속성에 조건부로 값 추가 (classappend) -->
<tr th:classappend="${user.admin} ? ' admin' : ''">
```

- th:attrappend, th:attrprepend는 **"속성이름=값"** 형식
- th:classappend는 **class 속성**만을 대상으로 한 전용 축약 문법
  - 내부적으로 th:attrappend="class=..."와 동일하게 작동
  - 보통 **조건에 따라 클래스 이름을 추가**할 때 사용

## 체크 박스, 라디오의 checked 속성 처리 – th:checked

```html
<input type="checkbox" th:checked="${user.active}">

<!-- user.active == true일 경우 -->
<input type="checkbox" checked>

<!-- user.active == false일 경우 -->
<input type="checkbox">
```

- **HTML의 checked 속성을 조건부로 삽입**하는 전용 속성
- th:checked 속성 값이 **false**일 경우, checked 속성은 **생략됨**

⚠️ HTML에서 checked 속성은 checked 속성의 값과 상관없이, **checked라는 속성만 있어도 체크가 된다.**

따라서 th:checked는 아래처럼 삼항 연산으로 checked를 처리하는 번거로움을 줄여준다.

```html
<input type="checkbox" th:attr="${user.active} ? 'checked' : null">
```

## 조건 분기 – th:if, th:unless, th:switch, th:case

```html
<p th:if="${user.age >= 20}">성인입니다.</p>
<p th:unless="${user.age >= 20}">미성년자입니다.</p>

<div th:switch="${user.role}">
  <p th:case="'ADMIN'">관리자입니다</p>
  <p th:case="'USER'">일반 사용자입니다</p>
  <p th:case="*">알 수 없는 권한입니다</p> <!-- default 역할 -->
</div>
```

- th:if는 참일 때 출력, th:unless는 거짓일 때 출력
- 조건이 맞지 않으면 **해당 태그 자체를 렌더링 하지 않음**
- th:case="\*"는 Java의 default:와 같은 역할

## 반복문 – th:each

```html
<tr th:each="user : ${userList}">
  <td th:text="${user.name}">홍길동</td>
</tr>
```

- 컬렉션(List, Set 등)이나 배열의 각 요소에 대해 해당 HTML 태그와 그 안의 내용을 반복해서 렌더링하는 데 사용
- Java의 foreach와 유사한 개념
- 선택적으로 반복 상태 정보를 제공하는 <strong>Loop 상태 객체(iterStat)</strong>를 받을 수 있다. (생략 시 변수명 + Stat)

```html
<tr th:each="user, iterStat : ${userList}">
  <td th:text="${iterStat.index}">0</td> <!-- 0부터 시작하는 인덱스 -->
  <td th:text="${iterStat.count}">1</td> <!-- 1부터 시작하는 순번 -->
  <td th:text="${iterStat.size}">총 개수</td>
  <td th:text="${iterStat.even}">짝수?</td>
  <td th:text="${iterStat.odd}">홀수?</td>
  <td th:text="${iterStat.first}">첫 번째?</td>
  <td th:text="${iterStat.last}">마지막?</td>
</tr>
```

- index : 현재 루프의 인덱스 (0부터 시작)
- count : 현재 루프의 순서 (1부터 시작)
- size : 전체 아이템 수
- even, odd : 짝수/홀수 여부
- first, last : 첫 번째/마지막 항목 여부

## 블록 – th:block

```
<th:block th:if="${condition}">
  <p>이 내용은 조건이 참일 때만 보입니다</p>
</th:block>
```

- 타임리프에서 제공하는 **가상의 태그**
- 실제 HTML에서는 **렌더링 되지 않고 제거됨**
- HTML 유효성을 지키면서 **템플릿 로직만 분리** 가능
- 주로 **조건문, 반복문, 변수 정의 등**에서 사용됨

HTML 태그에 직접 th:if, th:each 등을 지정할 수도 있지만, 다음과 같은 경우 th:block을 사용하는 것이 낫다.

- 조건을 걸고 싶은데, 감쌀 마땅한 태그가 없을 때
- 불필요한 div/span 등의 의미 없는 태그를 넣고 싶지 않을 때
- 여러 태그에 하나의 조건이나 반복을 적용하고 싶을 때

예시:

```html
<!-- 조건 분기용 래퍼 (th:if) -->
<th:block th:if="${user != null}">
  <p th:text="${user.name}"></p>
  <p th:text="${user.email}"></p>
</th:block>
```

```
<!-- 블록 임시 주석 처리 -->
<th:block th:if="${false}">
  <!-- 이 블록은 렌더링되지 않음 -->
</th:block>
```

```html
<!-- 반복 처리 (th:each) -->
<th:block th:each="user : ${users}">
  <p th:text="${user.name}"></p>
</th:block>
```

```html
<!-- 지역 변수 정의 (th:with) -->
<th:block th:with="firstUser=${users[0]}">
  <p th:text="${firstUser.name}"></p>
</th:block>
```

## 자바스크립트 인라인 – th:inline="javascript"

```xml
<script th:inline="javascript">
  let username = /*[[${user.name}]]*/ "default";
</script>
```

- **자바스크립트 코드 안에 타임리프 표현식을 안전하게 사용**하도록 해주는 기능
- 타임리프가 문자열 따옴표, 숫자 처리, 특수 문자 이스케이핑 등을 자동으로 처리해줌
- 즉, **타입 변환**과 **이스케이프** 처리를 알아서 해주기 때문에 안전하고 편리함
- "default"는 타임리프 렌더링이 되지 않았을 경우를 대비한 fallback 값

비교 예시:

```lua
const name = "${user.name}";
const name = [[${user.name}]];

const name = "[[${user.name}]]";
const name = /*[[${user.name}]]*/ "default";

const user = [[${user}]];
```

✔️ 위 예시를 &lt;script>로 실행:

```dart
const name = "${user.name}"; // 그대로 남음 (Thymeleaf 처리 X)
const name = kim;            // 심각한 문제 발생 (kim은 문자열이 아님)

const name = "kim";             // 문제 없어 보이지만 escape 불안정
const name = /*kim*/ "default"; // 주석만 바뀌고, "default"가 실제 값으로 들어감

const user = User(name=kim, age=25); // 자바 객체 toString 결과가 삽입됨
```

- th:inline="javascript" 없이 [[...]], /\*[[...]]\*/ 사용하면 **전혀 예상대로 동작하지 않음**.
- [[${user.name}]] → kimkim으로 대체되지만 **따옴표가 없음 → 자바스크립트 오류 발생**
- 객체 출력 시 JSON이 아닌 toString() 형식

✔️ 위 예시를 &lt;script th:inline="javascript">로 실행:

```dart
const name = "${user.name}"; // 그대로 출력 (템플릿 변수 아님)
const name = "kim";          // unescaped inline → 자동 따옴표 추가

const name = ""kim""; // escaped inline → 이중 따옴표 escape
const name = "kim";   // unescaped inline 주석 → 정상 동작

const user = {"name":"kim","age":25}; // 객체 → JSON으로 자동 변환
```

- [[...]], /\*[[...]]\*/ 모두 타임리프가 인식하여 **자바스크립트 문법에 맞는 escape 처리 및 타입 변환 수행**
- 문자 타입인 경우 ""를 포함시켜 준다.
- user 객체는 JSON으로 안전하게 출력됨

## &lt;script th:inline="javascript"> 블록 안에서 th:each 사용

```xml
<script th:inline="javascript">
    let names = [
        /*[# th:each="name : ${names}"]*/
            /*[[${name}]]*/ ,
        /*[/]*/
    ];
</script>
```

- **/\*[# ... ]\*/** ... **/\*[/]\*/** 주석 형태로 써야 함
- 마지막 쉼표 문제는 신경 쓸 필요 없음 (Thymeleaf는 자동으로 처리)

**템플릿 조각(프래그먼트) – th:fragment, th:insert, th:replace, th:include**

- **프래그먼트(fragment)**: 재사용 가능한 HTML 블록
- 여러 페이지에서 공통으로 사용되는 영역(헤더, 푸터 등)을 분리하고 재사용하기 위해 사용
- **th:fragment="이름"** 형식으로 블록에 이름을 붙임
- **th:fragment="이름 (param1, param2)"** 형식으로 파라미터를 전달하여 **동적 조각 생성**도 가능
- 프래그먼트는 **경로:: 이름** 형식으로 가져다 사용 가능 (예: th:replace="프래그먼트 경로 **::** 프래그먼트 이름")

```html
<!-- fragments/header.html -->
<header th:fragment="common-header">
  <span>공통 헤더입니다.</span>
</header>

<div th:fragment="common-param (param1, param2)">
  <span>공통 파람입니다.</span>
  <span>공통 param1 = [[${param1}]]</span>
  <span>공통 param2 = [[${param2}]]</span>
</div>
```

```html
<!-- main.html -->
<div th:insert="~{fragments/helloFragment :: commonFragment}"></div>

<div th:include="fragments/helloFragment :: commonFragment"></div>

<div th:replace="fragments/helloFragment :: commonFragment"></div>

<div th:replace="fragments/helloFragment :: paramFragment ('데이터1', '데이터2')"></div>
```

렌더링 결과:

```xml
<div><header>
  <span>공통 헤더입니다.</span>
</header></div>

<div>
  <span>공통 헤더입니다.</span>
</div>

<header>
  <span>공통 헤더입니다.</span>
</header>

<div>
  <span>공통 파람입니다.</span>
  <span>공통 param1 = 데이터1</span>
  <span>공통 param2 = 데이터2</span>
</div>
```

- th:insert → fragment 전체를 **자식으로 삽입** (원래 태그 유지)
- th:include → fragment의 **루트 태그를 제거하고, 내부 내용만 자식으로 삽입** (deprecated 됨)
- th:replace → 기존 태그를 **fragment 전체로 교체** (가장 자연스럽고 HTML 구조를 간결하게 유지할 수 있어 권장됨)

> ~{...}는 Thymeleaf의 URL 표현식 문법으로, 경로에 공백, 예약어 등이 포함될 경우 보다 안전하게 처리됨

## 템플릿 레이아웃

- 공통 UI 구조(헤더, 푸터 등)를 정의하고, 개별 화면은 콘텐츠만 바꾸는 방식
- 모든 페이지에 공통으로 들어가는 header, footer, nav 등을 반복하지 않기 위해 사용
- HTML 구조를 모듈화하여 중복 제거, 일관성 유지, 유지보수 편의성 확보
- 레이아웃 수정 시, 전체 페이지에 자동 반영되어 개발 생산성과 안정성 향상

```xml
<!--? fragments/header.html-->
<header th:fragment="common-header">
  <h1>My Web App</h1>
</header>
```

- 이름이 common-header인 프래그먼트(공통 헤더) 선언

```html
<!--? layout/base.html-->
<html th:fragment="layout (title, content)"
      xmlns:th="http://www.thymeleaf.org">
  <head>
    <meta charset="UTF-8">
    <title th:replace="${title}">기본 타이틀</title>
  </head>
  <body>
    <div th:replace="fragments/header :: common-header"></div>
    <main th:replace="${content}"></main>
  </body>
</html>
```

- 두 개의 파라미터(title, content)를 받는 템플릿 프래그먼트(공통 레이아웃) 선언
  - &lt;title th:replace="${title}">: 전달받은 title 프래그먼트를 삽입
  - &lt;main th:replace="${content}">: 전달받은 main 콘텐츠 프래그먼트를 삽입
- &lt;div th:replace="fragments/header :: common-header">: 외부 프래그먼트(header)를 삽입
- 이를 통해 매우 유연하게 레이아웃 구성 가능 (특히 페이지별 title, content가 다른 경우)

```html
<!--? pages/home.html-->
<html th:replace="layout/base :: layout (~{::title}, ~{::main})"
      xmlns:th="http://www.thymeleaf.org">
  <head>
    <title>홈 페이지</title>
  </head>
  <body>
    <main>
      <h2>환영합니다!</h2>
      <p>이곳은 홈입니다.</p>
    </main>
  </body>
</html>
```

- &lt;html th:replace="layout/base :: layout (**~{::title}, ~{::main**})">
  - layout/base.html의 layout 프래그먼트에 현재 페이지의 &lt;title>과 &lt;main>을 인자로 넘김
  - ~{::title}: 현재 문서의 &lt;title> 블록을 가져와 파라미터로 전달
  - ~{::main}: 현재 문서의 &lt;main> 블록을 가져와 파라미터로 전달
- 이를 통해 layout/base.html 템플릿에 전달되어, 전체 레이아웃 틀 안에 제목과 본문이 삽입됨

## 주석 처리 – 타임리프 파서 주석, 타임리프 프로토타입 주석

```xml
<!-- 표준 HTML 주석 (Standard HTML Comment) -->
```

- 타임리프 렌더링 후에도 **그대로 유지되어 HTML 소스에 포함됨**
- 즉, 브라우저에서 소스 보기나 개발자 도구에서 **그대로 노출됨**

```xml
<!--/* 타임리프 파서 주석 (Thymeleaf Parser-Level Comment) */-->
```

- **타임리프 템플릿 엔진이 렌더링 전에 완전히 제거**
- 최종 HTML 결과물에는 **아예 존재하지 않음** (개발자 도구에서도 안 보임)
- 실제 HTML 주석이 아닌 타임리프 전용 주석 문법
- HTML 유효성을 깨지 않으면서 안전하게 주석 처리 가능
- **민감한 서버 로직 설명**, **임시 코드 비활성화**

```xml
<!--/*/ 타임리프 프로토타입 주석 (Thymeleaf Prototype-Only Comment) /*/-->
```

- 타임리프 **렌더링 전에는 일반 HTML 주석**,
- **렌더링 시에는 주석이 해제**되어 내용이 실제로 렌더링 됨
- 브라우저에서 직접 열면 주석, **서버에서 실행하면 실제로 렌더링 되는** 하이브리드 주석 방식
- **프로토타입(디자인 시안)** 개발 시 유용
