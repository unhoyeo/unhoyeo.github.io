## 개념

- "때로는 당장 눈앞의 최선이 최고의 결과를 가져온다."
- **현재 차례의 최고의 답**을 찾는 문제
- 그런데 현재 최고의 답이 나중에 최선이 아닐 수도 있다.
- 따라서, **현재 최고의 답이 나중에 최선이 되는 이유**를 찾아야 한다. → 연습 중요!
- 이유를 증명하기 어려우면 **반례**가 있는지 찾아본다.
- 예를 들어, 1, 20, 30, 40원의 동전이 무한개 주어졌을 때 50원을 만드는 최소 동전의 개수를 구한다고 가정하자.
- 큰 금액의 동전부터 차감하게 된다면 40, 1 \* 10로, 총 11개가 필요하다.
- 하지만, 최소 개수는 30, 20 총 2개이다.
- 이런 식으로 반례가 있는지 찾아본다.

## 연습 문제 - 백준 11047번

```
10 4200
1
5
10
50
100
500
1000
5000
10000
50000
```

첫째 줄에 N과 K가 주어진다. (1 ≤ N ≤ 10, 1 ≤ K ≤ 100,000,000)

둘째 줄부터 N개의 줄에 동전의 가치 Ai가 오름차순으로 주어진다. (1 ≤ Ai ≤ 1,000,000, A1 = 1, i ≥ 2인 경우에 Ai는 Ai-1의 배수)

```
6
```

첫째 줄에 K원을 만드는데 필요한 동전 개수의 최솟값을 출력한다.

## 1. 아이디어

- 가치가 큰 동전부터 차감
- 반례? → (A1 = 1, i ≥ 2인 경우에 Ai는 Ai-1의 **배수**)라는 조건 덕분에 위에서 예로 들었던 반례는 없다!
- K를 동전 금액으로 나눈 뒤 남은 값으로 갱신 → for문으로 K가 0이 될 때까지 반복

## 2. 시간복잡도

- for문 → O(N)

## 3. 자료구조

- 동전 가치 → Ai ≤ 1,000,000 → **int[]**
- 남은 금액 → K ≤ 100,000,000 → **int**
- 사용 개수 → int

```java
import java.io.*;
import java.util.*;

class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        StringTokenizer st = new StringTokenizer(br.readLine());
        int N = Integer.parseInt(st.nextToken());
        int K = Integer.parseInt(st.nextToken());

        int[] arr = new int[N];
        for (int i = 0; i < N; i++) {
            arr[i] = Integer.parseInt(br.readLine());
        }

        int cnt = 0;
        for (int i = N - 1; i >= 0; i--) {
            if (arr[i] <= K) {
                cnt += K / arr[i];
                K %= arr[i];
            }
        }

        System.out.println(cnt);
    }
}
```

## 팁

- 실전에서 이 문제가 그리디 문제다라는 것을 생각하기가 어렵다.
- 그리고 그 문제가 그리디라는 보장이 없다.
- 그래서 그리디로 풀 수 있는 이유와 반례 찾는 연습을 해야 한다.
