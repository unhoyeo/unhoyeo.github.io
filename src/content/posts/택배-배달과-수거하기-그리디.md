## 문제 해결 전략

이 문제는 **그리디** 알고리즘을 사용하여 해결할 수 있다.

최소 이동 거리를 구하기 위해서는 **가장 먼 집부터 배달 및 수거를 처리**하여, 먼 거리를 여러 번 왕복하는 경우를 피하는 것이 핵심이다.

1. **역순 탐색**
   - <strong>가장 먼 집(n번째)</strong>부터 물류창고 쪽으로 이동하면서 배달/수거 작업을 처리한다.
   - 이렇게 하면 가장 비싼 비용(긴 이동 거리)이 드는 왕복을 최소화할 수 있다.
2. **필요 작업량 누적**
   - 먼 집부터 탐색하면서, **현재 처리해야 할 배달량과 수거량을 계속 누적**한다.
   - 이 값들은 <strong>"현재 위치보다 먼 집들에서 아직 처리하지 못한 작업량"</strong>을 의미한다.
3. **왕복 시점 결정**
   - 특정 집에 도착했을 때, 처리해야 할 배달이나 수거 작업량이 하나라도 남아있다면,
   - 트럭은 **반드시 그 집까지는 왕복 운행**을 해야 한다.
4. **왕복 처리**
   - 왕복이 필요하다고 판단되면, <strong>이동 거리(현재 집까지의 거리 × 2)</strong>를 총 이동 거리에 더한다.
   - **한 번의 왕복**으로 트럭은 최대 cap만큼의 배달과 cap만큼의 수거를 처리할 수 있다.
   - 따라서 **누적된 배달량과 수거량에서 cap만큼을 빼준다.**
   - 만약 한 번의 왕복으로 모든 누적 작업량을 처리할 수 없다면(예: 배달할 상자가 cap보다 많을 경우),
   - 처리할 작업량이 모두 **0 이하**가 될 때까지 **같은 거리를 여러 번 왕복**한다.

이 과정을 모든 집에 대해 반복하면 최소 이동 거리를 구할 수 있다.

## Java 코드

```java
class Solution {
    public long solution(int cap, int n, int[] deliveries, int[] pickups) {
        long answer = 0;

        // 처리해야 할 배달 및 수거량을 누적할 변수
        int deliverCount = 0;
        int pickupCount = 0;

        // 가장 먼 집부터 역순으로 순회
        for (int i = n - 1; i >= 0; i--) {
            // 현재 집에서 처리해야 할 배달/수거량을 누적
            deliverCount += deliveries[i];
            pickupCount += pickups[i];

            // 현재 집에 들러야 하는 경우 (처리할 배달 또는 수거가 있는 경우)
            while (deliverCount > 0 || pickupCount > 0) {
                // 이 집까지 왕복
                answer += (long) (i + 1) * 2;

                // 한 번의 왕복으로 cap만큼의 배달과 수거를 처리함
                deliverCount -= cap;
                pickupCount -= cap;

                // 처리할 배달 또는 수거가 없을 때까지 반복
            }
        }

        return answer;
    }
}
```

- **deliverCount, pickupCount**
  - 현재 위치(i)를 포함하여 더 먼 집들에서 아직 처리하지 못한 배달/수거 상자의 총 개수를 저장한다.
- **for (int i = n - 1; i >= 0; i--)**
  - 가장 먼 집부터 순회하여 그리디를 구현한다.
- **while (deliverCount > 0 || pickupCount > 0)**
  - i번째 집에 도착했을 때, 아직 처리할 작업이 남아있다면 왕복 운행이 필요함을 의미한다.
- **answer += (long)(i + 1) \* 2**
  - i번째 집의 위치는 i+1이므로, 왕복 거리는 (i+1) \* 2가 된다.
  - long으로 형변환하여 큰 숫자로 인한 오버플로우를 방지한다.
- **deliverCount -= cap; pickupCount -= cap;**
  - 한 번의 왕복으로 최대 cap만큼의 용량을 사용할 수 있으므로, 남은 작업량에서 cap을 빼준다.
  - while 루프를 통해 작업량이 cap보다 많더라도, 여러 번 왕복하는 경우를 올바르게 계산할 수 있다.
  - 작업량이 **음수**가 되는 것은 해당 왕복에서 **용량이 남았음**을 의미하며,
  - 이 남은 용량은 **더 가까운 집의 작업을 처리**하는 데 사용될 수 있다.
