## 인터넷에서 컴퓨터 둘은 어떻게 통신할까?

인터넷은 복잡한 망으로 되어있기 때문에 통신을 위한 최소한의 규칙이 있어야 한다. 그것을 <strong>인터넷 프로토콜(IP)</strong>이라고 한다. 일단 클라이언트가 IP 주소를 부여 받아야 한다. 그리고 서버도 IP 주소가 있어야 한다. 그러면 인터넷 프로토콜은 지정한 IP 주소에 '패킷'이라는 통신 단위로 데이터를 전달한다.

인터넷 프로토콜(Internet Protocol, IP)은 네트워크 상에서 데이터를 송수신하는 규칙과 방법을 정의하는 통신 프로토콜이다.

IP는 컴퓨터 네트워크에서 데이터를 **패킷**(packet) 단위로 전달하며, 네트워크의 각 장치(노드)들이 서로를 식별하고 통신할 수 있도록 하는 역할을 한다.

---

## 1. 인터넷 프로토콜의 역할

IP는 **패킷 스위칭** 방식으로 데이터를 전달하는데, 다음과 같은 주요 기능을 수행한다.

## 1) 주소 지정 (Addressing)

- 네트워크 상의 모든 장치는 **IP 주소**를 가져야 한다.
- IP 주소는 목적지와 발신지를 식별하는 역할을 한다.
- 대표적인 IP 주소 체계
  - **IPv4** (예: 192.168.1.1)
  - **IPv6** (예: 2001:db8::ff00:42:8329)

## 2) 패킷화 (Packetization)

- 데이터를 일정 크기의 패킷으로 나누어 전송한다.
- 각 패킷에는 발신지 IP, 목적지 IP, 데이터, 헤더 정보 등이 포함된다.
- 패킷은 목적지까지 독립적으로 전송되며, 도착 후 다시 조립된다.

## 3) 라우팅 (Routing)

- 데이터가 목적지까지 도달하도록 경로를 결정한다.
- 네트워크 상의 <strong>라우터(Router)</strong>가 패킷을 분석하고 적절한 방향으로 전달한다.
- 동적으로 최적의 경로를 선택하며, 여러 개의 경로가 존재할 수 있다.

## 4) 단편화 (Fragmentation)

- 네트워크의 전송 단위(**MTU**, Maximum Transmission Unit)가 다를 수 있기 때문에, 큰 패킷을 잘게 나누어 전송하는 기능이다.
- 수신 측에서 다시 조립된다.

---

## 2. 인터넷 프로토콜의 종류

## 1) IPv4 (Internet Protocol version 4)

- **32비트** 주소 체계를 사용한다. (2^32 = 약 43억 개의 주소)
- 표기법: 192.168.0.1 (점으로 구분된 4개의 8비트 숫자)
- 한정된 IP 주소 문제를 해결하기 위해 **NAT**(Network Address Translation) 기술을 사용한다.
- 패킷 헤더 크기가 작아 속도가 빠르다.

## 2) IPv6 (Internet Protocol version 6)

- **128비트** 주소 체계를 사용한다. (2^128 = 사실상 무한한 주소 공간)
- 표기법: 2001:db8::ff00:42:8329 (콜론으로 구분된 8개의 16비트 블록)
- 주소 부족 문제를 해결하고 보안성을 강화한다.
- 패킷 크기가 커서 처리 속도가 IPv4보다 낮을 수 있다.

## 3. IP와 함께 사용되는 프로토콜

## 1) 전송 계층 프로토콜

- **TCP (Transmission Control Protocol)**
  - 연결 지향 프로토콜 (3-way Handshake)
  - 신뢰성 보장 (패킷 손실 시 재전송)
  - 순서 보장 (순서 번호(Sequence Number) 사용)
  - 흐름 제어 (송·수신 속도를 맞추기 위해 윈도우 크기 조정)
  - 혼잡 제어 (네트워크가 과부하되지 않도록 혼잡 제어 알고리즘 적용)
  - 예: HTTP, FTP, SMTP 등 신뢰성이 중요한 서비스
- **UDP (User Datagram Protocol)**
  - 빠른 전송을 위해 신뢰성을 포기한 프로토콜 (하얀 도화지에 비유)
  - 연결을 설정하지 않음 (비연결형)
  - 순서 보장하지 않음
  - IP와 거의 같지만, PORT와 체크섬 정도만 추가되어 있다.
  - 예: 동영상 스트리밍, 온라인 게임, VoIP

## 2) 네트워크 계층 프로토콜

- **ICMP (Internet Control Message Protocol)**
  - 네트워크 오류 메시지를 전달하는 프로토콜
  - 예: ping 명령어
- **ARP (Address Resolution Protocol)**
  - IP 주소를 MAC 주소로 변환하는 프로토콜
  - LAN(Local Area Network) 환경에서 사용됨

## 4. IP 주소 할당 방식

## 1) 고정 IP (Static IP)

- 수동으로 설정된 IP 주소 (변하지 않음)
- 서버, 네트워크 장비 등에 주로 사용

## 2) 동적 IP (Dynamic IP)

- DHCP 서버를 통해 자동으로 할당
- 일반 사용자의 인터넷 연결에 주로 사용

## 5. IP 패킷 구조 (IPv4 기준)

IPv4 패킷은 크게 **헤더(Header)와 데이터(Data)** 부분으로 구성

|  |  |  |
| --- | --- | --- |
| **필드** | **크기 (비트)** | **설명** |
| 버전 | 4 | IP 버전 (IPv4: 4) |
| 헤더 길이 | 4 | 헤더의 길이 |
| 서비스 타입 | 8 | 패킷의 우선순위 |
| 총 길이 | 16 | 패킷의 전체 길이 |
| 식별자 | 16 | 패킷의 고유 식별자 |
| 플래그 | 3 | 패킷 분할 관련 정보 |
| 프래그먼트 오프셋 | 13 | 조각화된 패킷의 순서 |
| TTL | 8 | 패킷의 생존 시간 (Time To Live) |
| 프로토콜 | 8 | 상위 계층 프로토콜 (TCP: 6, UDP: 17) |
| 헤더 체크섬 | 16 | 오류 검사 |
| 출발지 IP | 32 | 패킷을 보낸 장치의 IP 주소 |
| 목적지 IP | 32 | 패킷을 받을 장치의 IP 주소 |
| 옵션 | 가변적 | 추가적인 정보 |
| 데이터 | 가변적 | 실제 전송할 내용 |

## 6. IP의 한계 및 해결책

## 1) 주소 부족 문제 → IPv6 도입

- IPv4 주소 공간이 거의 고갈됨 → IPv6로 확장

## 2) 보안 문제 → IPsec 사용

- IP는 기본적으로 보안이 없음 → **IPsec**(암호화 및 인증 기능 제공) 사용

## 3) 트래픽 혼잡 문제 → QoS (Quality of Service)

- 실시간 트래픽(음성, 영상) 관리를 위해 QoS 기능 도입

비연결성 → TCP 3-Way Handshake

패킷을 받을 대상이 없거나 서비스 불능 상태여도 패킷을 전송

대상 서버가 패킷을 받을 수 있는 상태인지 모름

비신뢰성, 비순서 → TCP 재전송, 순서 번호

중간에 패킷이 사라지거나 순서대로 도착하지 않을 수 있음

프로그램 구분 문제 → PORT

PORT

## 1. 포트(Port)란?

네트워크에서 프로세스(프로그램) 간의 통신을 구별하는 논리적인 번호

컴퓨터가 하나의 IP 주소를 가지더라도, 여러 개의 서비스(웹, 이메일, FTP 등)를 동시에 실행할 수 있도록 각 서비스마다 고유한 포트 번호를 할당한다. 즉, 같은 IP 주소라도 포트 번호를 통해 어떤 서비스로 접속할지를 결정한다.

## 2. 포트 번호의 범위

포트 번호는 **16비트(0~65535) 범위**의 숫자로 구성된다.

IANA(Internet Assigned Numbers Authority)에서 포트 번호를 관리하며, 크게 3가지 범위로 나뉜다.

|  |  |  |
| --- | --- | --- |
| **0 ~ 1023** | Well-Known Ports (공인 포트) | HTTP(80), HTTPS(443), FTP(21) 등 널리 사용되는 프로토콜 |
| **1024 ~ 49151** | Registered Ports (등록 포트) | 특정 기업/서비스에서 등록하여 사용 (ex: 게임 서버, 응용 프로그램) |
| **49152 ~ 65535** | Dynamic / Private Ports (임시 포트) | 클라이언트가 동적으로 할당받는 포트 (ex: 임시 연결) |

✔ 0~1023번 포트는 운영체제가 관리하며, 일반 사용자는 기본적으로 사용할 수 없음!

## 3. 주요 포트 번호 및 사용 사례

|  |  |  |
| --- | --- | --- |
| **20, 21** | FTP | 파일 전송 (20: 데이터, 21: 제어) |
| **22** | SSH | 원격 접속 (보안 쉘) |
| **23** | Telnet | 원격 접속 (보안 없음) |
| **25** | SMTP | 이메일 발송 (메일 서버) |
| **53** | DNS | 도메인 이름 변환 (IP 주소 조회) |
| **80** | HTTP | 웹사이트 (비보안) |
| **443** | HTTPS | 보안 웹사이트 (SSL/TLS 암호화) |
| **3306** | MySQL | MySQL 데이터베이스 |
| **6379** | Redis | Redis 캐시 |
| **8080** | HTTP | 대체 HTTP 포트 (Tomcat 등) |

✔ 포트 번호만 보고도 어떤 서비스가 실행 중인지 알 수 있음!

## 4. TCP 포트와 UDP 포트의 차이

포트는 TCP와 UDP에서 각각 다르게 사용됩니다.

|  |  |  |
| --- | --- | --- |
| **특징** | **TCP 포트** | **UDP 포트** |
| 프로토콜 특성 | 신뢰성 보장 (데이터 확인, 재전송) | 빠른 전송, 신뢰성 보장 없음 |
| 사용 예시 | 웹 서버(HTTP/HTTPS), 이메일(SMTP, POP3), FTP 등 | DNS, VoIP, 스트리밍, 온라인 게임 등 |
| 연결 방식 | 3-Way Handshake 사용 | 비연결형(Handshake 없음) |

✔ 같은 포트 번호라도 TCP와 UDP에서 다른 용도로 사용 가능!

## 예시:

- TCP 53번 포트 → **DNS 요청 응답**

- UDP 53번 포트 → **빠른 DNS 질의**

## 5. 포트의 동작 원리

## 클라이언트-서버 모델에서의 포트 역할

1. **클라이언트(예: 웹 브라우저)**

- 클라이언트는 <strong>임시 포트(49152~65535)</strong>를 사용하여 요청을 보냄.

2. **서버(예: 웹 서버)**

- 서버는 <strong>고정된 포트(예: 80번)</strong>에서 요청을 대기.

3. **응답**

- 서버는 클라이언트가 사용한 임시 포트로 응답을 전송.

✔ 예시: 클라이언트가 웹사이트(192.168.1.1:80)에 접속하는 과정

```
클라이언트 (랜덤 포트: 52345) → 서버 (IP: 192.168.1.1, 포트: 80)
서버 (포트: 80) → 클라이언트 (랜덤 포트: 52345)
```

✔ 즉, 클라이언트는 동적 포트를, 서버는 고정 포트를 사용하여 통신!

## 6. 포트 스캔과 보안 이슈

## 포트 스캔 (Port Scanning)

해커들은 네트워크의 열려 있는 포트를 검색하여 보안 취약점을 찾는 포트 스캐닝을 시도할 수 있습니다.

## 보안 위협

- **불필요한 포트 개방**: 공격자가 침입할 수 있는 경로 제공

- **포트 스캐닝 공격**: 서버의 열린 포트를 찾아 취약점 공격

## 보안 대책

✅ **불필요한 포트 차단** (방화벽에서 필요하지 않은 포트 닫기)

✅ **SSH(22) 포트 변경** (기본 포트 대신 다른 포트 사용)

✅ **포트 필터링 및 모니터링** (IDS/IPS 시스템 활용)

✅ **방화벽 및 ACL 설정** (허가된 IP만 특정 포트 접근 허용)

---

## 7. 방화벽(Firewall)과 포트

방화벽(Firewall)은 특정 포트의 트래픽을 허용하거나 차단하여 네트워크를 보호합니다.

## 방화벽 설정 예시

```
# 22번 (SSH) 허용
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 80번 (HTTP) 허용
iptables -A INPUT -p tcp --dport 80 -j ACCEPT

# 3306번 (MySQL) 차단
iptables -A INPUT -p tcp --dport 3306 -j DROP
```

✔ 이렇게 하면 MySQL(3306) 포트를 차단하여 외부 접근을 방지 가능!

---

## 8. 결론

- 포트는 프로세스 간 통신을 구별하는 역할을 하며, TCP와 UDP에서 각각 사용됨.

- 0~65535번까지 존재하며, 1023번 이하의 포트는 공인 포트(WELL-KNOWN PORT)로 사용됨.

- 클라이언트는 동적 포트, 서버는 고정 포트를 사용하여 통신.

- 방화벽을 이용해 불필요한 포트를 차단하고, 보안 설정을 강화해야 함.

✔ **포트를 이해하면 네트워크 트래픽 분석, 서버 보안, 방화벽 설정 등을 효과적으로 수행 가능!** ?

## DNS(Domain Name System)

## 1. DNS란?

**도메인 이름을 IP 주소로 변환**하는 시스템

사용자가 웹사이트 주소(www.example.com)를 입력하면, DNS 서버가 해당 도메인에 대응하는 IP 주소(예: 192.168.1.1)를 반환한다.

**즉, DNS는 인터넷의 “전화번호부” 역할을 하며, 사람이 이해하기 쉬운 도메인명을 컴퓨터가 사용하는 IP 주소로 변환하는 기능을 한다.**

---

## 2. 왜 DNS가 필요한가?

컴퓨터는 숫자로 된 IP 주소(예: 192.168.1.1, 2001:db8::ff00:42:8329)를 사용해 통신한다.

하지만 사람이 이런 IP 주소를 기억하는 것은 어렵고, 또한 IP 주소는 변경될 수 있다.

따라서 DNS를 이용해 도메인명을 사용할 수 있도록 합니다.

✅ DNS 없을 때:

```
서버 접속 → 172.217.161.142 (Google의 IP 주소 입력)
```

✅ DNS 있을 때:

```
서버 접속 → www.google.com (DNS가 자동으로 IP 주소 변환)
```

✔ DNS 덕분에 도메인명만 기억하면 쉽게 인터넷을 사용할 수 있음!

## 3. DNS의 동작 과정

## 사용자가 웹사이트 접속 시 DNS 작동 흐름

1️⃣ 사용자가 www.example.com 입력

2️⃣ 로컬 DNS 캐시 확인 (브라우저 또는 OS)

3️⃣ 캐시에 없으면 ISP(인터넷 서비스 제공자)의 DNS 서버에 질의

4️⃣ ISP DNS 서버가 DNS 계층 구조를 따라 도메인의 IP 주소를 조회

5️⃣ 조회된 IP 주소를 클라이언트에게 반환

6️⃣ 브라우저가 해당 IP 주소로 연결하여 웹사이트 접속 완료

✔ 이 과정은 밀리초 단위로 실행되며, 사용자는 거의 지연 없이 웹사이트에 접속 가능!

## 7. 결론

인터넷 프로토콜(IP)은 네트워크 상에서 데이터를 패킷 단위로 송수신하는 핵심적인 역할을 합니다. IPv4는 여전히 널리 사용되지만, 주소 부족 문제 해결을 위해 IPv6로 점차 전환되고 있습니다. 또한, IP는 TCP, UDP와 같은 전송 계층 프로토콜과 함께 동작하며, 패킷 스위칭 방식으로 최적의 경로를 찾아 데이터를 전달합니다.

추가적으로 보안 및 성능 향상을 위해 IPsec, NAT, QoS 등의 기술이 함께 사용됩니다. IP는 현대 인터넷 환경에서 필수적인 요소이며, 네트워크 통신을 이해하는 데 있어 중요한 개념입니다.

## 1. TCP/IP 개요

<strong>TCP/IP(Transmission Control Protocol/Internet Protocol)</strong>는 인터넷 및 대부분의 네트워크에서 사용되는 기본 프로토콜 스택입니다.

- 데이터를 패킷(Packet) 단위로 전송하는 IP(Internet Protocol)와

- 신뢰성 있는 데이터 전송을 보장하는 TCP(Transmission Control Protocol)가 핵심 요소입니다.

TCP/IP는 네트워크 계층 모델로, 여러 개의 프로토콜이 결합된 프로토콜 스택이며, 네트워크를 통해 데이터를 정확하고 효율적으로 전송할 수 있도록 합니다.

## 3. TCP(Transmission Control Protocol)

## 3.1 TCP의 특징

TCP는 신뢰성 있는 데이터 전송을 위해 **연결형 프로토콜**을 사용합니다.

- **패킷 손실 방지:** 패킷이 손실되면 재전송

- **순서 보장:** 데이터가 순서대로 도착하도록 관리

- **흐름 제어:** 송·수신 속도 조절

- **혼잡 제어:** 네트워크 혼잡을 방지하는 기능 제공

## 3.2 TCP의 주요 기능

## 1) 3-Way Handshake (연결 설정)

TCP는 **3-Way Handshake** 과정을 통해 신뢰성 있는 연결을 설정합니다.

1. 클라이언트 → 서버: SYN 전송 (연결 요청)

2. 서버 → 클라이언트: SYN + ACK 전송 (요청 수락)

3. 클라이언트 → 서버: ACK 전송 (연결 확립)

✔ 연결이 확립되면 데이터 송수신 시작

## 2) 데이터 전송 및 흐름 제어

- **슬라이딩 윈도우(Sliding Window)**:

- 수신 측이 처리할 수 있는 데이터 크기를 송신 측에 알려줌

- 수신 측이 가용한 버퍼 크기에 맞춰 전송 속도를 조절

- 네트워크 혼잡을 완화하는 역할

## 3) 오류 및 손실 감지 (재전송)

- **ACK (Acknowledgment)**: 정상적으로 수신된 패킷에 대해 확인 응답 전송

- **패킷 손실 감지 후 재전송**:

- 타이머 기반 재전송: 일정 시간이 지나도 ACK가 오지 않으면 재전송

- 빠른 재전송: 3번 연속 같은 ACK가 오면 손실된 것으로 판단하고 즉시 재전송

## 4) 4-Way Handshake (연결 종료)

TCP 연결 종료는 **4-Way Handshake**로 진행됩니다.

1. 클라이언트 → 서버: FIN 전송 (연결 종료 요청)

2. 서버 → 클라이언트: ACK 전송 (FIN 요청 확인)

3. 서버 → 클라이언트: FIN 전송 (서버도 연결 종료)

4. 클라이언트 → 서버: ACK 전송 (연결 종료 완료)

✔ 연결이 종료되면 모든 자원이 해제됨

## 4. IP (Internet Protocol)

## 4.1 IP의 역할

IP는 네트워크 계층에서 패킷을 목적지까지 전달하는 역할을 합니다.

- **비연결형 프로토콜** (데이터를 패킷 단위로 독립적으로 전송)

- **주소 지정 및 패킷 전달**

- **라우팅(Routing) 지원** (최적 경로 선택)

## 4.2 IP 주소

IP는 IPv4(32비트)와 IPv6(128비트) 두 가지 주소 체계를 사용합니다.

- IPv4: 192.168.1.1 (4옥텟)

- IPv6: 2001:db8::ff00:42:8329 (16바이트)

## 4.3 IP 패킷 구조

IP 패킷은 헤더(Header) + 데이터(Data)로 구성됩니다.

## 필드크기설명

| 서비스 타입 | 8비트 | QoS 기능 |
| 총 길이 | 16비트 | 패킷의 전체 크기 |

| 출발지 IP | 32비트 | 발신지 주소 |
| 목적지 IP | 32비트 | 수신지 주소 |

## 5.1 UDP의 특징

## TCP (Transmission Control Protocol) 상세 설명

TCP(Transmission Control Protocol)는 신뢰성 있는 데이터 전송을 제공하는 **연결형(Connected) 프로토콜**입니다.

네트워크 상에서 데이터를 순서대로, 오류 없이 전달하기 위해 다양한 기술을 사용합니다.

---

## 1. TCP의 주요 특징

## 특징설명

|  |  |
| --- | --- |
| **연결 지향(Connection-oriented)** | 데이터를 보내기 전 3-Way Handshake 과정을 통해 연결을 설정 |
| **신뢰성 보장(Reliable Delivery)** | 데이터 손실 발생 시 재전송하여 신뢰성을 보장 |
| **순서 보장(Ordered Delivery)** | 송신한 순서대로 데이터가 도착하도록 순서 번호(Sequence Number) 사용 |
| **흐름 제어(Flow Control)** | 송·수신 속도를 맞추기 위해 윈도우(Window) 크기 조정 |
| **혼잡 제어(Congestion Control)** | 네트워크가 과부하되지 않도록 혼잡 제어 알고리즘 적용 |

---

## 2. TCP 3-Way Handshake (연결 설정 과정)

TCP는 <strong>3-Way Handshake(3단계 핸드셰이크)</strong>를 통해 신뢰성 있는 연결을 설정합니다.

## 과정 개요

TCP 연결이 설정되는 과정:

1. 클라이언트 → 서버: SYN (연결 요청)

2. 서버 → 클라이언트: SYN + ACK (연결 요청 수락 및 응답)

3. 클라이언트 → 서버: ACK (연결 확립 완료)

> **SYN(Synchronize):** 연결 요청

> **ACK(Acknowledgment):** 응답 신호

---

## 3-Way Handshake 과정 상세

## 1단계: SYN (클라이언트 → 서버)

- 클라이언트는 서버에 연결 요청 메시지(SYN)를 보냄.

- TCP 헤더에 **초기 순서 번호(Initial Sequence Number, ISN)** 포함.

- 이 메시지를 받은 서버는 연결을 준비.

**패킷 구조 (SYN)**

```
[SYN]  SEQ=1000, ACK=0
```

---

## 2단계: SYN + ACK (서버 → 클라이언트)

- 서버는 클라이언트의 연결 요청을 수락하고, 응답으로 **SYN + ACK** 패킷을 보냄.

- 서버도 자신의 초기 순서 번호(ISN)를 설정하여 클라이언트에게 전달.

**패킷 구조 (SYN+ACK)**

```
[SYN, ACK]  SEQ=2000, ACK=1001
```

- SEQ=2000 (서버의 초기 순서 번호)

- ACK=1001 (클라이언트가 보낸 SEQ + 1 값)

---

## 3단계: ACK (클라이언트 → 서버)

- 클라이언트는 서버의 SYN + ACK 메시지를 받고, ACK 패킷을 보냄.

- 이제 연결이 확립되었으며, 데이터를 송수신할 준비가 완료됨.

**패킷 구조 (ACK)**

```
[ACK]  SEQ=1001, ACK=2001
```

- SEQ=1001 (클라이언트가 보낼 데이터의 순서 번호)

- ACK=2001 (서버가 보낸 SEQ + 1 값)

✔ 이제 TCP 연결이 정상적으로 설정됨!

---

## 3. TCP 데이터 전송 과정

연결이 설정되면 데이터를 송수신할 수 있습니다.

TCP는 순서 번호(Sequence Number)와 확인 응답(ACK)을 활용하여 데이터가 순서대로 도착하도록 보장합니다.

## 송신 측 (클라이언트)

- 데이터를 일정 크기의 패킷으로 분할하여 전송.

- 각 패킷에는 <strong>순서 번호(SEQ)</strong>가 포함됨.

**패킷 구조 (데이터 전송)**

```
[DATA] SEQ=1001, ACK=2001, DATA="Hello"
```

---

## 수신 측 (서버)

- 패킷을 수신하면 데이터가 정상적으로 도착했는지 확인.

- 문제없이 수신되면, 다음에 받을 데이터를 알려주는 ACK 패킷을 전송.

**패킷 구조 (ACK 응답)**

```
[ACK] SEQ=2001, ACK=1006
```

- ACK=1006 (클라이언트가 보낸 SEQ + 데이터 길이)

✔ 이러한 방식으로 데이터를 순서대로, 안전하게 전송 가능!

---

## 4. TCP 4-Way Handshake (연결 종료 과정)

TCP는 <strong>4-Way Handshake(4단계 핸드셰이크)</strong>를 통해 연결을 종료합니다.

## 과정 개요

1. 클라이언트 → 서버: FIN (연결 종료 요청)

2. 서버 → 클라이언트: ACK (요청 확인)

3. 서버 → 클라이언트: FIN (서버도 종료 요청)

4. 클라이언트 → 서버: ACK (연결 종료 완료)

> **FIN(Finish):** 연결 종료 요청

---

## 4-Way Handshake 과정 상세

## 1단계: 클라이언트가 FIN 전송

- 클라이언트는 서버에 FIN 패킷을 보내고 “데이터 전송을 종료”할 것임을 알림.

**패킷 구조 (FIN)**

```
[FIN] SEQ=1006, ACK=2001
```

---

## 2단계: 서버가 ACK 전송

- 서버는 클라이언트의 종료 요청을 확인하고 ACK 패킷을 보냄.

**패킷 구조 (ACK)**

```
[ACK] SEQ=2001, ACK=1007
```

---

## 3단계: 서버가 FIN 전송

- 서버도 데이터 전송을 종료하기 위해 FIN 패킷을 보냄.

**패킷 구조 (FIN)**

```
[FIN] SEQ=2001, ACK=1007
```

---

## 4단계: 클라이언트가 ACK 전송

- 클라이언트가 ACK를 보내고 **연결이 완전히 종료됨**.

**패킷 구조 (ACK)**

```
[ACK] SEQ=1007, ACK=2002
```

✔ 이제 모든 연결이 해제되고, TCP 세션이 종료됨!

---

## 5. TCP 흐름 제어 (Flow Control)

TCP는 송신자와 수신자의 속도 차이를 조정하기 위해 <strong>흐름 제어(Flow Control)</strong>를 제공합니다.

- **윈도우(Window) 크기 조정**: 수신자는 송신자에게 “내가 받을 수 있는 데이터 크기”를 알려줌.

- **슬라이딩 윈도우(Sliding Window)**: 데이터가 성공적으로 수신되면 윈도우를 이동하여 새로운 데이터를 받음.

✔ 이렇게 하면 데이터가 유실되지 않고, 네트워크 성능이 최적화됨!

---

## 6. TCP 혼잡 제어 (Congestion Control)

네트워크가 과부하되지 않도록 하기 위해 **혼잡 제어**를 수행합니다.

- **느린 시작(Slow Start)**: 처음에는 작은 데이터 패킷을 보내다가 점점 증가.

- **혼잡 회피(Congestion Avoidance)**: 네트워크 상태를 보고 적절히 데이터 크기 조절.

- **패킷 손실 감지 시 재전송**: 네트워크 혼잡을 방지.

✔ 이런 기법 덕분에 TCP는 안정적인 데이터 전송을 보장!

---

## 7. 결론

- TCP는 연결형 프로토콜이며, 신뢰성 있는 데이터 전송을 보장.

- **3-Way Handshake**로 연결을 설정하고, **4-Way Handshake**로 종료.

- 흐름 제어 & 혼잡 제어를 통해 안정적인 통신을 제공.

**TCP는 웹, 이메일, 파일 전송 등 신뢰성이 중요한 서비스에 필수적!**
